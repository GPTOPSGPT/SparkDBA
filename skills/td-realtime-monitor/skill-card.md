# Skill Card — td-realtime-monitor

| field | value |
|---|---|
| Description | See `SKILL.md` frontmatter. |
| Use case | Zero-code monitors on plant telemetry from one sentence (selector + metric + threshold + window), evaluated every 5 s with an alert journal. |
| Owner | Team GPTOPS (3rd NVIDIA DGX Spark Hackathon) |
| Version | 0.1.0 |
| License | Apache-2.0 |
| Dependencies | td-connector (tdlib.py); the monitor evaluator service (deploy/monitor.sh) |
| Data access | Read-only through td-connector; writes only its own monitor list and alert journal in $SPARKDBA_DATA. |
| Risks | A wrong threshold floods or silences alerts. |
| Mitigations | Strict validation of every field; the SKILL.md requires asking when the target or threshold is missing and confirming the rule back; monitors never change devices or data; at most one alert per monitor and device per minute. |
| Limitations | Five metrics and simple > / < rules over one window; journal only, no paging or webhooks. |
| Ethical notes | Runs fully on-premises on a DGX Spark; plant telemetry is never sent to an external service. Findings are advisory; people decide on maintenance. |
| Evaluation | `evals/evals.json` (positive and negative tasks, incl. should-not-trigger cases); results in `BENCHMARK.md`, generated by `python -m evals.run` with and without skills on the same model. Final batch: plant device + fault accuracy 16.7% without skills, 100% with skills (18 runs each). |
| Provenance | Shape follows the "one connector + four advisors" pattern; the agent, rules and simulator are the team's own. |
