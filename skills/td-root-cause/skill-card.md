# Skill Card — td-root-cause

| field | value |
|---|---|
| Description | See `SKILL.md` frontmatter. |
| Use case | For a yield drop, alarm or metric jump: rank device-level fault hypotheses and verify each against the data, with the SQL trace behind every number. |
| Owner | Team GPTOPS (3rd NVIDIA DGX Spark Hackathon) |
| Version | 0.1.0 |
| License | Apache-2.0 |
| Dependencies | td-connector (tdlib.py) |
| Data access | Read-only through td-connector. |
| Risks | A confident wrong device sends maintenance to the wrong machine. |
| Mitigations | Deterministic ranking rules with the numbers and SQL trace shown; the answer contract requires DEVICE, evidence and a ruled-out alternative; healthy is a valid answer; nothing is executed. |
| Limitations | Five fault types plus healthy; thresholds tuned on the simulated plant; needs about 30 minutes of history. |
| Ethical notes | Runs fully on-premises on a DGX Spark; plant telemetry is never sent to an external service. Findings are advisory; people decide on maintenance. |
| Evaluation | `evals/evals.json` (positive and negative tasks, incl. should-not-trigger cases); results in `BENCHMARK.md`, generated by `python -m evals.run` with and without skills on the same model. Final batch: plant device + fault accuracy 16.7% without skills, 100% with skills (18 runs each). |
| Provenance | Shape follows the "one connector + four advisors" pattern; the agent, rules and simulator are the team's own. |
