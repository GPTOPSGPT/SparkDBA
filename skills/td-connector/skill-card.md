# Skill Card — td-connector

| field | value |
|---|---|
| Description | See `SKILL.md` frontmatter. |
| Use case | Guarded read access to the plant's TDengine database: schema and device discovery, one read-only statement per call. |
| Owner | Team GPTOPS (3rd NVIDIA DGX Spark Hackathon) |
| Version | 0.1.0 |
| License | Apache-2.0 |
| Dependencies | Python 3.12, taospy, TDengine 3.x; the td-* advisors import its tdlib.py |
| Data access | Read: database plant (super tables sensors and output, their tags). Up to 500 rows per query. |
| Risks | TDengine OSS has no GRANT, so the database itself cannot make the agent's user read-only. |
| Mitigations | Server-side allowlist: exactly one SELECT / SHOW / DESCRIBE, write and admin keywords refused, rows capped; the simulator writes with a separate user. |
| Limitations | Read-only by allowlist, not by database privilege; queries should be time-bounded (one row per device per second). |
| Ethical notes | Runs fully on-premises on a DGX Spark; plant telemetry is never sent to an external service. Findings are advisory; people decide on maintenance. |
| Evaluation | `evals/evals.json` (positive and negative tasks, incl. should-not-trigger cases); results in `BENCHMARK.md`, generated by `python -m evals.run` with and without skills on the same model. Final batch: plant device + fault accuracy 16.7% without skills, 100% with skills (18 runs each). |
| Provenance | Shape follows the "one connector + four advisors" pattern; the agent, rules and simulator are the team's own. |
