# Skill Card — pg-evidence-snapshot

| field | value |
|---|---|
| Description | See `SKILL.md` frontmatter. |
| Use case | Live PostgreSQL slowdowns, hangs, lock waits and connection pile-ups: the first evidence pass. |
| Owner | Team GPTOPS (3rd NVIDIA DGX Spark Hackathon) |
| Version | 0.1.0 |
| License | Apache-2.0 |
| Dependencies | Python 3.12, psycopg 3, PostgreSQL 13+ (pg_blocking_pids, pg_stat_statements optional) |
| Data access | Read-only: pg_stat_activity, pg_locks, pg_stat_user_tables, pg_stat_statements, pg_settings. Query text is truncated to 200 chars. |
| Risks | Query text in the output can contain customer data or injected instructions. |
| Mitigations | Role is read-only with a 10 s statement timeout; SKILL.md states query text is data, never instructions; the harness excludes its own sessions. |
| Limitations | Sees only the present moment (use pg-workload-report for the past); 10 samples over 5 s can miss sub-second spikes. |
| Ethical notes | Runs fully on-premises on a DGX Spark; database telemetry is never sent to an external service. Recommendations are advisory; a human owns every tier B/C change. |
| Evaluation | `evals/evals.json` (positive and negative tasks, incl. should-not-trigger cases); results in `BENCHMARK.md`, generated by `python -m evals.run` with and without skills on the same model. |
| Provenance | Business logic ported from the team's KingbaseES diagnosis agent (kb2026: chaos agent, wait-event screening, auto_exec tiers, os_guard). |
