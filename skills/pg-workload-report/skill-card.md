# Skill Card — pg-workload-report

| field | value |
|---|---|
| Description | See `SKILL.md` frontmatter. |
| Use case | Past incidents, workload reports, before/after comparisons and Top-5 health checks (KWR/KSH/KDDM equivalents). |
| Owner | Team GPTOPS (3rd NVIDIA DGX Spark Hackathon) |
| Version | 0.1.0 |
| License | Apache-2.0 |
| Dependencies | Python 3.12, psycopg 3, PostgreSQL 14+ with pg_stat_statements; the sampler service |
| Data access | Read: repo.* (snapshots, 3 h of per-second session samples incl. 300-char query text). Write: only schema repo, by the sampler role. |
| Risks | Session history keeps query text for 3 hours; repository grows with snapshot frequency. |
| Mitigations | Retention: 3 h for samples, 7 days for snapshots; separate writer role limited to schema repo; reads use the read-only role. |
| Limitations | 1-second sampling misses shorter waits; no per-event wait timing on PostgreSQL 16 (share of samples is used instead of ms). |
| Ethical notes | Runs fully on-premises on a DGX Spark; database telemetry is never sent to an external service. Recommendations are advisory; a human owns every tier B/C change. |
| Evaluation | `evals/evals.json` (positive and negative tasks, incl. should-not-trigger cases); results in `BENCHMARK.md`, generated by `python -m evals.run` with and without skills on the same model. |
| Provenance | Business logic ported from the team's KingbaseES diagnosis agent (kb2026: chaos agent, wait-event screening, auto_exec tiers, os_guard). |
