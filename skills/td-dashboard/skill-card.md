# Skill Card — td-dashboard

| field | value |
|---|---|
| Description | See `SKILL.md` frontmatter. |
| Use case | Save an analysis as a live panel (title + guarded SELECT + line or bar chart + refresh) that the SparkDBA UI renders. |
| Owner | Team GPTOPS (3rd NVIDIA DGX Spark Hackathon) |
| Version | 0.1.0 |
| License | Apache-2.0 |
| Dependencies | td-connector (tdlib.py); the SparkDBA web UI to render panels |
| Data access | Read-only through td-connector; writes only its own panel list in $SPARKDBA_DATA. |
| Risks | An unbounded query on a panel could load the database on every refresh. |
| Mitigations | Same SQL allowlist as the connector; the SQL runs once before saving; the SKILL.md requires time bounds and INTERVAL aggregation; refresh clamped to 5–300 s. |
| Limitations | Line and bar charts; first column is the x axis. |
| Ethical notes | Runs fully on-premises on a DGX Spark; plant telemetry is never sent to an external service. Findings are advisory; people decide on maintenance. |
| Evaluation | `evals/evals.json` (positive and negative tasks, incl. should-not-trigger cases); results in `BENCHMARK.md`, generated by `python -m evals.run` with and without skills on the same model. Final batch: plant device + fault accuracy 16.7% without skills, 100% with skills (18 runs each). |
| Provenance | Shape follows the "one connector + four advisors" pattern; the agent, rules and simulator are the team's own. |
