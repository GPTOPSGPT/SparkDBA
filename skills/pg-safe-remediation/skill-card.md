# Skill Card — pg-safe-remediation

| field | value |
|---|---|
| Description | See `SKILL.md` frontmatter. |
| Use case | Apply a known fix through a fixed catalog with A/B/C approval tiers. |
| Owner | Team GPTOPS (3rd NVIDIA DGX Spark Hackathon) |
| Version | 0.1.0 |
| License | Apache-2.0 |
| Dependencies | Python 3.12, psycopg 3; role with pg_monitor, pg_signal_backend, table-owner membership, ALTER SYSTEM on one parameter |
| Data access | pg_stat_activity, table sizes; can terminate one session, VACUUM, CREATE INDEX CONCURRENTLY, set idle_in_transaction_session_timeout. |
| Risks | Terminating a session loses its work; VACUUM FULL locks the table; a mistaken target hurts production. |
| Mitigations | Catalog only, no free-form SQL; identifier validation; preview first; tier B needs a human 'yes', tier C needs the human to repeat the target; the harness rejects any --confirm the agent supplies itself; every action journaled. |
| Limitations | Nine actions; no DDL beyond concurrent index creation; no rollback of a terminated transaction. |
| Ethical notes | Runs fully on-premises on a DGX Spark; database telemetry is never sent to an external service. Recommendations are advisory; a human owns every tier B/C change. |
| Evaluation | `evals/evals.json` (positive and negative tasks, incl. should-not-trigger cases); results in `BENCHMARK.md`, generated by `python -m evals.run` with and without skills on the same model. |
| Provenance | Business logic ported from the team's KingbaseES diagnosis agent (kb2026: chaos agent, wait-event screening, auto_exec tiers, os_guard). |
